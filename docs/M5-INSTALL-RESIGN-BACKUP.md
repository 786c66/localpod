# M5 安装、重签与备份

> 适用：LocalPod 自用构建（iOS 17+、iPhone-only、纯音频、免费 Apple ID 侧载）。
> 本文只描述当前仓库已验证的代码行为；真机步骤凡未在本机执行，均明确标注“待真机验证”。
> 安装签名的基础步骤以 [`M0-SIGNING.md`](M0-SIGNING.md) 第 1–2 节为准，本文补充 M5 的提醒、重签和备份语义。

## 0. 一句话结论

- 用 **同一 Bundle ID（`com.localpod.app`）覆盖安装/重签**，App 容器通常保留：SwiftData 资料库、进度、队列、播放列表、设置、`Application Support/Media` 媒体文件都在容器内。
- **不要删除 App，不要改 Bundle ID**。删除或换 ID 会换沙盒容器，资料库和媒体都会丢失。
- `Application Support/Media` 明确标记了 `isExcludedFromBackup`，所以设备备份/迁移**可能不包含媒体文件**；数据库和设置可能恢复，但媒体需要重新导入，导入后按 SHA-256 指纹**重链**到原条目（保留条目 ID、进度、播放列表和队列引用）。
- 免费 Personal Team 的描述文件通常约 7 天到期。App 会在诊断页显示剩余天数，并可选地在到期前 2 天 10:00 发本地通知。通知是否真正送达**未在真机验证**；诊断页横幅始终是兜底。

## 1. Xcode 直接安装（推荐基线）

完整首次准备（开发者模式、信任证书、Personal Team）见 [`M0-SIGNING.md`](M0-SIGNING.md) 第 1–2 节。此处只列与 M5 相关的检查点：

1. 打开 `LocalPod.xcodeproj`（修改 `project.yml` 或新增文件后先运行 `xcodegen generate`）。
2. 选择 **LocalPod** target → **Signing & Capabilities**：
   - Team 选择自己的 Personal Team；
   - 勾选 Automatically manage signing；
   - **不要**添加 App Group、iCloud、Push、StoreKit 等 capability。本项目不需要，也没有这些 entitlement。
3. `PRODUCT_BUNDLE_IDENTIFIER` 保持 `com.localpod.app`（`project.yml` 中的仓库默认值）。若被占用必须改，则从第一次安装起始终使用同一个新 ID，并在本文所有步骤中替换。
4. 连接 iPhone，选择该设备，Run。首次启动如被拦，到 iPhone **设置 → 通用 → VPN 与设备管理** 信任开发者证书。
5. 打开 **诊断** 页确认：
   - Bundle ID、Team、App ID 与 Xcode 一致；
   - 描述文件到期时间和剩余天数；
   - 有描述文件时顶部出现签名横幅（无描述文件的模拟器不显示）。
6. 打开 **设置**，确认「签名」分区的「签名到期提醒」开关存在。

> Xcode 覆盖安装（Run）不会先删除 App。安装失败时优先检查设备信任、开发者模式、免费账号设备数量限制；**不要为了“重装干净”先删 App**，除非已经接受数据丢失并完成可恢复的备份/重导准备。

## 2. SideStore / AltStore 续签（可选，本仓库未实测）

SideStore/AltStore 可以作为“同一 Bundle ID 的 7 天刷新”替代 Xcode 直连，但本仓库**没有在真机上验证过**，下面是使用边界而不是通过结论：

- 必须继续使用 **同一 Bundle ID**；在工具中确认刷新的是 `com.localpod.app`，不要新建第二个 App ID。
- iOS 侧需完成配对/描述文件安装；免费 Apple ID 的 App ID 数量、设备数量和 7 天刷新限制以 Apple 当前政策为准。
- 后台自动刷新不保证成功：工具未运行、网络不可用、证书状态变化、系统回收都会导致过期。建议保留 Xcode 作为兜底。
- 某些刷新/安装路径可能先卸载再安装。**能否保留容器取决于工具实现和当时状态，不能假设一定保留**。刷新前先用 Files/Finder 保留原始媒体文件，确保可以按第 4 节重导。
- 不要在 SideStore/AltStore 中更改 Bundle ID 或删除 App 后再刷新。若工具要求删除才能继续，视为“可能丢数据”的维护操作。
- 本文不声称 SideStore/AltStore 已通过本项目的安装、刷新或数据保留验收。

## 3. 7 天到期、本地提醒与日历兜底

### 3.1 到期行为

- 免费 Personal Team 的描述文件通常约 7 天到期；实际时间以诊断页为准（可能因 Apple 策略变化而不同）。
- 到期后 App 图标可能仍在，但启动会被系统拒绝。此时**不要删除 App**；用同一 Bundle ID 重新签名/覆盖安装。
- 诊断页显示剩余天数和建议文案（`signingExpiryBanner`）：有描述文件且有到期时间才显示；模拟器/未签名构建没有 `embedded.mobileprovision`，不显示。

### 3.2 App 内本地提醒

- 设置项：**设置 → 签名 → 签名到期提醒**。
- 默认开启，但不代表已获得通知权限：App 启动时只读取授权状态，**不会弹权限框**；只有把开关从“关”切到“开”时才请求通知权限。
  - 若首次安装后开关本来就是开启状态，请先关闭再开启一次以触发系统授权；也可以在 iOS **设置 → 通知 → LocalPod** 中检查（只有请求过授权后才会出现）。
- 授权后，若存在描述文件到期时间且尚未过期，会在**到期前 2 天的本地时间 10:00** 安排一条本地通知；使用固定标识 `localpod.signing.expiry`，重复安排会替换旧请求，不会堆叠。
- 关闭开关会取消待发送的提醒。过期、没有描述文件、或已经错过“到期前 2 天 10:00”时不安排通知。
- 拒绝通知权限时静默跳过，不反复弹窗；诊断页横幅仍然有效。
- 该通知是 `UNUserNotificationCenter` 的本地日历触发器，**不涉及 Push entitlement**。通知是否实际送达依赖系统通知权限、专注模式和通知摘要设置，**本仓库未在真机验证送达**。

### 3.3 日历兜底

不要只依赖本地通知，建议在首次安装/每次重签后立即建立一个日历事件：

- 时间：安装当天 + 5 天（比 7 天到期提前约 2 天），或直接设为诊断页到期日的**前一天 10:00**；
- 标题：`LocalPod 重签`;
- 备注：`用 Xcode/SideStore 以 com.localpod.app 覆盖安装；不要删除 App，不要改 Bundle ID。`
- 日历事件与 App 的通知互相独立；即使通知权限被拒绝也能提醒。

## 4. 重签保留什么、什么情况下会丢

同一 Bundle ID、覆盖安装/重签时，App 的 sandbox 容器通常原样保留：

| 内容 | 位置 | 覆盖重签后 |
| --- | --- | --- |
| 资料库条目、合集、导入历史 | `Application Support/default.store*`（SwiftData） | 保留 |
| 播放进度、队列、播放列表 | 同上（SwiftData） | 保留 |
| 设置（倍速、跳过、恢复、自动下一集、签名提醒开关） | `UserDefaults` | 保留 |
| 媒体文件 | `Application Support/Media` | 保留（覆盖安装不清理） |
| 封面缓存 | `Caches/Artwork` | 通常可继续使用；系统可清理缓存 |
| 收件箱待导入文件 | `Documents/Import` | 保留 |
| 导入 JSON 报告 | `Application Support/ImportReports` | 保留 |

会丢数据的操作：

- 在 iPhone 上**删除 App** 后再安装：容器被删除，资料库/媒体/进度/播放列表全部丢失。
- **更换 Bundle ID**：新容器，等同于新 App。
- 使用某些侧载工具的“卸载后刷新”路径：可能清除容器。把这类操作当成有丢数据风险的重装。
- 还原设备后只恢复了数据库、但没有恢复媒体（见第 5 节）：条目会变成缺失，需要重导。

重签后建议在诊断页核对：到期时间更新、资料库条目数不变、随便播放一条旧媒体、检查一个播放列表/队列仍在。

## 5. 备份语义（Finder 加密备份、iCloud 备份、Quick Start）

### 5.1 关键事实：媒体默认不进设备备份

代码中 `MediaStorage.mediaRootURL()` 和 `stagingRootURL()` 对目录设置了：

```swift
values.isExcludedFromBackup = true
```

因此 `Application Support/Media`（用户导入/示例的媒体）以及临时 staging 目录会被排除在设备备份之外。Finder 的“加密本地备份”只改变备份的加密方式，**不会覆盖 `isExcludedFromBackup`**；加密备份仍可能不包含这些媒体文件。

可能被备份/迁移的内容：

- `Application Support/default.store`、`-shm`、`-wal`（资料库、进度、队列、播放列表）；
- `UserDefaults` 设置；
- `Documents/Import` 与 `Application Support/ImportReports`（未被显式排除）；
- App 包本身（重装/更新时由 Xcode 或侧载工具提供）。

### 5.2 从备份恢复后的预期

1. 如果数据库和设置恢复、媒体未恢复：启动维护会把找不到文件的条目标记为缺失（`isMissing`）。
2. 把原始媒体文件重新导入（文件夹、文件选择、收件箱或打开方式均可）。
3. 导入引擎会读取 SHA-256 指纹；对已缺失且指纹相同的条目执行**重链**，而不是新建重复条目：
   - 更新 `relativePath`、大小、时长、封面和 `isMissing = false`；
   - 保留原条目 ID、播放进度、播放列表引用和队列引用；
   - 导入报告把这类文件计入「重链」（`relinkedCount`），而不是「导入」。
4. 若文件内容已改变（重新转码、剪辑、不同码率），指纹不同，会作为新条目导入，旧条目仍缺失。

### 5.3 Quick Start / 直接换机

Quick Start 属于设备迁移，其行为可能与 iCloud/Finder 备份不同，且**本仓库没有真机验证**。不要假设媒体一定迁移过去。最稳妥的做法：

- 迁移前把原始媒体文件夹保留在电脑或 iCloud Drive（LocalPod 本身不申请 iCloud 容器）；
- 迁移后先打开诊断页，确认媒体条目是否缺失；
- 缺失则按 5.2 重导；不要删除 App 或资料库。

Finder 加密备份适合保留数据库/设置；它不是媒体归档方案。**媒体的可靠备份 = 保留原始文件**，需要时重导重链。
